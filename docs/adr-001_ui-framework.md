# ADR-001: ターミナル UI フレームワークに rich + prompt_toolkit を採用する

- ステータス: 承認
- 日付: 2026-06-30
- 関連: D5（`docs/context.md`）

## コンテキスト

ローカルで動く対話型（REPL）のコーディングエージェントを作る。Phase 1 は UI/UX のみを対象とし、「継続して使える触り心地」を最優先で固める方針（D3, D4）。一方で全体方針として「ハーネスは小さく・シンプルに」保ちたい。

REPL の入力（複数行・履歴・キーバインド・補完）と出力（Markdown レンダリング・色付き表示・スピナー・差分表示）をどの層で実現するかを決める必要がある。

## 選択肢

1. **標準ライブラリのみ**（`input()` + `print()` + `readline`）
   - 利点: 依存ゼロで最軽量。
   - 欠点: 複数行入力・Markdown 表示・スピナー等を自前実装する必要があり、Phase 1 の狙い（使い勝手）に対して体験が貧弱。

2. **`rich` + `prompt_toolkit`**
   - 利点: `prompt_toolkit` が複数行入力・履歴・キーバインド・補完・安全なペーストを、`rich` が Markdown レンダリング・パネル・スピナー・差分表示を、いずれも少ないコードで提供する。Claude Code 的な操作感を薄い実装で得られる。
   - 欠点: 依存が2つ増える。

3. **`textual` でフル TUI**
   - 利点: 画面分割・スクロール領域などリッチな UI が可能。
   - 欠点: 実装・概念ともに重く、「軽量・シンプル」から外れる。Phase 1 にはオーバーキル。

## 決定

**選択肢 2（`rich` + `prompt_toolkit`）を採用する。**

「ハーネスは小さく」と「使い勝手は重要」は一見ぶつかるが、この2ライブラリは“小さいコードで良い体験”を出すための定番であり、両立できる。入力は `prompt_toolkit`、出力は `rich` と役割を分ける。

## 結果

- 依存に `rich` と `prompt_toolkit` を追加する。
- REPL らしい体験（複数行入力・履歴・Markdown 出力・スピナー）を薄い実装で得られる。
- フル TUI が必要になった場合は将来 `textual`（同じ作者）への移行を再検討する余地がある。
